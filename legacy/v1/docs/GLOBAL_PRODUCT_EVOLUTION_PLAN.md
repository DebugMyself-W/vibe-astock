# Vibe-Astock 全局产品迭代方案

> 状态：讨论基线 v1.0
> 日期：2026-09-18
> 当前约束：先确定产品、领域模型、数据门槛和验收标准，再进入功能实现。

## 1. 产品结论

Vibe-Astock 不建设另一个综合行情终端，也不复制连板天梯的全部模块。产品终局是：

> **连板短线的复盘—验证—校准系统：收盘形成可验证判断，次日竞价和盘中持续验证，收盘后自动归因并校准规则。**

核心闭环：

```text
收盘事实整理
  → 形成市场判断与明日验证条件
  → 09:25 竞价首次验证
  → 盘中状态变化与异常提醒
  → 15:00 收盘最终对账
  → 历史统计与规则校准
```

系统始终只回答三个问题：

1. 当前盘面处于什么状态？
2. 相比上一个关键截面发生了什么变化？
3. 昨晚的判断还成立吗？

## 2. 产品原则

### 2.1 必须坚持

- 收盘复盘是产品大脑；竞价和盘中是验证器。
- 硬指标负责判定，生成式 AI 负责解释，不让 AI 参与确定性排名。
- 同一事实、题材和股票在不同页面使用同一份数据与同一口径。
- 历史页面只能展示当时已经获得的数据，不用收盘结果冒充盘中认知。
- 每个判断必须附带依据、数据时间、来源、验证状态和失效条件。
- 缺数据时显示“数据不足”，不强行生成结论。
- 只对超过噪声阈值的变化生成事件和提醒。

### 2.2 奥卡姆剃刀

- 能并入“今日验证”的，不新增一级页面。
- 能在统一题材抽屉中完成的，不建立多个题材子页面。
- 外部平台已成熟且不参与核心闭环的能力，使用深链接跳转。
- 只有直接改变“判断是否成立”的数据，才进入首页。
- 每增加一个模块，必须明确它替代了什么人工步骤。

## 3. 信息架构

最终只保留三个主要业务入口：

### 3.1 今日验证

竞价和盘中主入口，展示：

- 交易阶段时间轴；
- 昨晚判断与今日验证；
- 情绪状态；
- 主线题材；
- 接力结构；
- 昨日强势股反馈；
- 盘中变化时间轴；
- 关键风险。

### 3.2 收盘复盘

延续并强化现有优势：

- 赚钱效应与亏钱效应；
- 分层晋级率与梯队断层；
- 封板质量；
- 题材事件树；
- 昨日强势股反馈矩阵；
- 情绪周期与历史分位；
- 次日验证条件。

### 3.3 历史校准

用于长期学习，而不是展示虚假“胜率”：

- 每日判断与验证结果；
- 指标提前量；
- 条件误报、漏报和数据缺失；
- 不同情绪阶段下的适用性；
- 阈值版本与历史回测；
- AI 叙述与硬指标冲突记录。

“首板分析”“实时盘面”“近5天热度”在迁移完成前保留，之后根据用户路径逐步并入上述入口，不进行一次性删除。

## 4. 领域模型

### 4.1 TradingSnapshot：交易截面

记录某个时点用户真实可见的市场事实。

关键字段：交易日、截面类型、采集时间、市场宽度、涨跌停、炸板、梯队、题材、核心股票、数据覆盖率、来源状态。

标准截面：

- `previous_close`：前一交易日收盘；
- `auction_0925`：09:25 竞价定盘；
- `morning_1000`：上午稳定观察点；
- `midday_1130`：午间截面；
- `late_1430`：尾盘截面；
- `close_1500`：收盘冻结。

### 4.2 MarketRegime：市场状态

沿用并统一六个维度：

- 赚钱反馈；
- 接力晋级；
- 封板质量；
- 亏钱效应；
- 梯队结构；
- 市场宽度。

输出包括情绪阶段、风险等级、置信度、覆盖率、核心证据和缺失项。

### 4.3 ThemeState：题材状态

记录真实事件题材，而非行业替代物。

包括：生命周期、强度、扩散、核心股、补涨、跟随、涨停/连板/炸板成员、昨日反馈、资金变化和相关事件。

### 4.4 StockRole：股票角色

角色是客观的盘面关系，不是推荐标签：

- 高度核心；
- 题材核心；
- 容量核心；
- 补涨；
- 跟随；
- 风险样本；
- 角色待确认。

### 4.5 ValidationRule：验证条件

由收盘复盘创建。每条必须包含：

- 被验证的判断；
- 固定指标；
- 今日基准；
- 预期方向；
- 有意义变化阈值；
- 最早可验证截面；
- 失效时间；
- 生成依据。

### 4.6 ValidationResult：验证结果

统一状态：

- `pending`：待验证；
- `watching`：待观察；
- `satisfied`：已满足；
- `invalidated`：已证伪；
- `insufficient_data`：数据不足；
- `expired`：已失效。

状态变化只追加，不覆盖历史。

### 4.7 MarketEvent：市场事件

由相邻截面差异生成，例如：

- 炸板率显著恶化；
- 1进2或2进3跌破参考线；
- 最高标断板；
- 题材由扩散转分歧；
- 新题材形成有效联动；
- 核心股反馈整体转弱；
- 验证条件满足或被证伪。

事件必须包含前值、后值、阈值、发生时间、影响范围与证据链接。

## 5. 数据能力与门槛

| 数据能力 | 最低频率 | 必须落盘 | 首次进入版本 | 准入门槛 |
|---|---:|---:|---:|---|
| 09:25竞价结果 | 每日一次 | 是 | V1 | 日期、价格、涨幅、成交额稳定可取 |
| 涨停/跌停/炸板池 | 30—60秒 | 是 | 已有/V1 | 场次一致、制度感知、失败不伪造 |
| 全市场宽度 | 30—60秒 | 是 | 已有/V1 | 覆盖率可见，历史可复现 |
| 连板梯队与晋级 | 30—60秒 | 是 | 已有/V1 | 分层计算，反包结构不丢失 |
| 题材原因与成员 | 分钟/收盘 | 是 | 已有/V1 | 不用行业冒充题材 |
| 核心股实时反馈 | 30—60秒 | 是 | V1 | 股票身份和昨日角色冻结 |
| 封单逐帧变化 | 5—15秒 | 是 | V2候选 | 稳定、合规、可回放后才上线 |
| 题材分时 | 1分钟 | 最好 | V3 | 成分映射和历史一致 |
| 监管异动 | 事件触发 | 是 | V2/V3 | 规则版本可追溯 |

任何数据未达到门槛时，只能进入实验区，不能进入首页结论和外部提醒。

## 6. 版本路线图

### V0：统一内核

目标：在不大改界面的前提下建立统一数据语言。

交付：

- 七个核心领域模型；
- 关键截面落盘机制；
- 验证条件生命周期；
- 事件差异引擎骨架；
- 数据来源、覆盖率和口径元数据；
- 旧页面到新模型的适配层。

验收门槛：

- 同一验证条件能跨收盘、竞价、盘中、收盘更新；
- 任意结论可以定位到截面和原始数据；
- 历史日重新打开不会使用未来数据；
- 现有复盘结果不发生无解释的口径变化。

### V1：最小闭环

目标：第一次完成“昨晚判断—今天验证—收盘对账”。

交付：

- “今日验证”一级入口；
- 09:25竞价验证；
- 10:00上午状态；
- 15:00收盘最终对账；
- 验证状态卡和证据详情；
- 昨日强势股反馈；
- 主线题材和接力结构摘要；
- 收盘复盘自动引用今日验证过程。

验收门槛：

- 至少80%的有效复盘日能生成2—5条可机器验证条件；
- 09:25数据成功日中，验证结果可自动产出且可解释；
- 重跑同一历史日结果一致；
- 用户不打开其他页面也能判断昨晚结论是否仍成立。

### V2：盘中演化

目标：从静态状态升级为关键变化。

交付：

- 11:30与14:30截面；
- 盘中事件时间轴；
- 情绪阶段切换；
- 题材扩散、分歧和退潮事件；
- 核心股、最高标和梯队变化；
- 站内异常提醒；
- 事件去重、冷却和噪声阈值。

验收门槛：

- 每日事件数量可控，默认不超过10条高价值事件；
- 相同事件不会重复刷屏；
- 每条事件可说明“为什么重要”；
- 数据中断不会被误判为盘面变化。

### V3：题材工作台

目标：让题材成为统一下钻单位。

交付：

- 统一题材详情抽屉；
- 题材生命周期、强度和扩散；
- 核心股、补涨、跟随角色；
- 题材与核心股分时叠加；
- 事件、涨停原因和昨日反馈；
- 题材验证条件。

验收门槛：

- 从首页点击题材后，无需切换页面即可完成核心核查；
- 题材成员、原因和角色使用统一口径；
- 缺少成分映射时明确降级，不自动切换其他板块。

### V4：历史校准

目标：判断规则是否真的提供提前量。

交付：

- 判断和验证结果档案；
- 指标领先性、误报、漏报和缺失统计；
- 不同情绪阶段的条件表现；
- 阈值版本管理；
- 规则回测和人工确认；
- AI叙述与硬指标冲突检测。

验收门槛：

- 所有统计展示样本量和适用范围；
- 不将相关性包装为胜率或收益承诺；
- 阈值修改不会覆盖旧版本历史结果。

### V5：克制的个性化

目标：支持不同短线体系，但不做复杂工作台编辑器。

交付：

- 用户规则包；
- 自选股和关注题材验证；
- 紧凑/标准两种信息密度；
- 站内提醒偏好；
- 可选的外部提醒通道。

验收门槛：

- 默认设置即可工作；
- 用户不需要维护几十个参数；
- 个性化不会改变客观事实口径。

## 7. 依赖关系

```text
V0 统一内核
 └─ V1 最小闭环
     ├─ V2 盘中演化
     │   └─ V3 题材工作台
     └─ V4 历史校准
         └─ V5 个性化
```

V2不能先于V1：没有验证条件，盘中事件会退化成普通行情提醒。
V4不能先于V0：没有版本化快照和规则，历史统计无法复现。
逐帧封单不是V1前置条件，只有通过数据可行性验证后才进入V2。

## 8. UI 设计基线

UI文件：`docs/vibe-astock-today-validation-ui-v1.png`

### 8.1 页面层级

1. 顶部：页面目标、当前阶段、更新时间、刷新与问AI。
2. 时间轴：09:25、10:00、11:30、14:30、15:00。
3. 验证摘要：进度、已满足、待观察、已证伪。
4. 左侧主列：昨晚判断、情绪状态、主线题材。
5. 右侧监控列：盘中变化、昨日反馈、接力结构、关键风险。

### 8.2 交互规则

- 点击验证条件：查看基准、阈值、证据和状态历史。
- 点击题材：打开统一题材抽屉。
- 点击事件：突出相关验证条件、题材和股票。
- 点击时间轴：回看当时截面；历史截面不得混入未来数据。
- 问AI：只携带当前截面和选中对象，不默认发送整页无关数据。
- 状态颜色只表达验证状态，涨跌颜色继续遵循全站规则。

### 8.3 响应式策略

- 桌面端：双列分析布局。
- 平板端：主列在上、监控列在下。
- 移动端：时间轴横向滚动，验证条件优先，图表折叠为摘要。
- 第一版不支持自由拖拽、任意列宽和任意模块编排。

## 9. 明确非目标

- 不建设完整行情终端、完整K线工具或交易下单能力。
- 不建设全网新闻、电报、社交热榜和公告平台。
- 不建设全市场3D、装饰性复杂热力图。
- 不建设自由拖拽、自由缩放的重型工作台。
- 不增加独立AI人格或重复聊天入口。
- 不提供个股确定性买卖结论。
- 不自动修改生产规则和阈值。
- 不把未回测指标包装成收益、胜率或预测能力。

外部平台负责完整原始行情和深度资料；Vibe-Astock只保留参与核心判断和验证闭环的摘要，并提供明确深链接。

## 10. 全局成功指标

### 用户价值

- 收盘复盘后，用户能在3分钟内形成2—5条明确验证条件。
- 次日打开“今日验证”后，30秒内知道昨晚判断是否仍成立。
- 收盘后无需人工回忆盘中过程即可完成对账。

### 数据质量

- 历史截面可复现率；
- 关键数据源成功率和延迟；
- 题材原因覆盖率；
- 验证条件可计算率；
- 数据中断误报率。

### 产品克制

- 首页默认可见高价值模块不超过8个；
- 默认每日高价值事件不超过10条；
- 一级业务入口控制在3个；
- 每个新增模块必须明确替代的人工步骤和退出条件。

## 11. 开发前决策

已确认：

- 产品采用“收盘复盘为核心、盘中自动验证”的方向；
- 盘中一级入口命名为“今日验证”；
- 第一版只承诺09:25定盘验证，为09:15和09:20预留模型；
- 第一版仅做站内状态变化，不做微信、飞书推送；
- 第一版不建设完整全天信息流。

进入实现前仍需完成：

1. 09:25竞价数据源可行性验证；
2. 现有模型到V0领域模型的字段映射；
3. 验证条件的首批固定指标集；
4. 各截面的采集和落盘策略；
5. V1验收用例和历史回放样本日。
